# بوت إشعارات المهام — Notion → Telegram

السكربت يشتغل وظيفتين بنفس الدورة:

1. **إشعارات تيليجرام** للمهام الجديدة المكلّف بيها أحد أعضاء الفريق.
2. **مزامنة بوابة العميل (Mayadeen)** — نسخ باتجاه واحد من قاعدة المهام الرئيسية إلى قاعدة `Mayadeen Productions`.

## شنو يسوي البوت؟

يفحص البوت قاعدة البيانات **كل دقيقة تقريباً** (عبر GitHub Actions)، وفي كل فحص يسوي التالي:

1. يستعلم من قاعدة بيانات المهام في Notion (iPlugn Tasks) عن كل مهمة **مؤشَّر عليها Assignee** و**خانة Notified غير مفعّلة**.
2. لكل مهمة، يطابق أول Assignee مع قائمة الفريق (`TEAM_MAP`) ويرسل له رسالة تيليجرام فيها: اسم المهمة، المشروع والأولوية، الموعد النهائي، ورابط صفحة المهمة في Notion.
3. بعد نجاح الإرسال، يفعّل خانة **Notified** على المهمة حتى ما تنرسل مرة ثانية.
4. إذا الشخص المكلّف مو موجود في `TEAM_MAP`، يتخطى المهمة ويسجلها في السجل (log) بدون ما يوقف باقي المهام.

> **ملاحظة:** البوت يرسل إشعاراً مرة واحدة فقط لكل مهمة. إذا أردت إعادة الإرسال، ألغِ تفعيل خانة Notified في Notion وسيرسلها البوت في الدورة القادمة.

## مزامنة بوابة العميل (Mayadeen Productions)

بنفس الدورة، يزامن السكربت المهام إلى قاعدة بوابة العميل. المزامنة **باتجاه واحد فقط**: من القاعدة الرئيسية إلى البوابة، ولا يُكتب أي شيء بالاتجاه المعاكس.

**شنو يحدد إن المهمة تروح للعميل؟** شرط واحد فقط: `Client/Project = Mayadeen approval`.
المهام المؤشرة **`Mayadeen`** العادية تبقى داخلية وما تظهر بالبوابة.

في كل دورة:

1. يجيب كل المهام اللي `Client/Project = Mayadeen approval` من القاعدة الرئيسية.
2. يطابق كل مهمة مع صف في البوابة عن طريق عمود **Source ID** (= معرّف صفحة المهمة الأصلية).
3. **ما موجود صف؟** ينشئ صف جديد. **موجود؟** يحدّث `Task Name` و`Status` و`Final Link` إذا تغيّرت.
4. المهمة تغيّر تصنيفها من `Mayadeen approval` لأي شي ثاني، أو انحذفت؟ يؤرشف صفها في البوابة (أرشفة، مو حذف نهائي — تنرجع من Notion).

> **ملاحظة:** تغيير `Client/Project` من `Mayadeen approval` إلى `Mayadeen` هي طريقة **سحب** المهمة من البوابة — صفها راح ينأرشف بالدورة الجاية.

### الأعمدة

| العمود في البوابة | يتزامن؟ |
|---|---|
| `Task Name` | ✅ من القاعدة الرئيسية |
| `Status` | ✅ من القاعدة الرئيسية |
| `Final Link` | ✅ من القاعدة الرئيسية |
| `Source ID` | ✅ يُكتب مرة وحدة عند الإنشاء (مفتاح المطابقة — خلّيه مخفي) |
| `comment` | ❌ **أبداً** — هذا العمود مِلك العميل، السكربت ما يلمسه |

الأعمدة `Script` و`Priority` و`Assignee` و`Footage Link` و`Deadline` و`Notified` **ما تنرسل للبوابة إطلاقاً** — تبقى داخلية.

> **ملاحظات:**
> - أي صف تنشئه يدوياً داخل البوابة بدون `Source ID` ما يلمسه السكربت (لا يحدّثه ولا يؤرشفه).
> - إذا انتسخ صف بالغلط وصار صفين بنفس `Source ID`، يبقي الأقدم ويؤرشف الباقي.
> - أي تعديل يسويه العميل على `Task Name` أو `Status` أو `Final Link` داخل البوابة راح ينكتب فوقه بالدورة الجاية — التعديلات تنراد بالقاعدة الرئيسية.

ملخص كل دورة يظهر بالسجل بسطر واحد:

```
Portal: X Mayadeen approval tasks, Y created, Z updated, W archived, V failed
```

> **مهم للإعداد:** لازم تكامل Notion (نفس `NOTION_TOKEN`) يكون مضاف لقاعدة **Mayadeen Productions** بصلاحية تعديل، مو بس للقاعدة الرئيسية. من صفحة البوابة: **⋯ ← Connections ← أضف التكامل**. بدونها راح تفشل المزامنة بخطأ صلاحيات وتظهر بالسجل.

## كيف أضيف عضو جديد للفريق؟

تحتاج معلومتين عن العضو الجديد:

### 1. معرّف المستخدم في Notion (Notion user ID)

- تأكد أولاً أن العضو مُضاف إلى مساحة عمل Notion ويظهر في قائمة Assignee.
- أسهل طريقة: من أي صفحة في Notion، اكتب `@اسم-العضو` ثم انسخ رابط الإشارة (Copy link)، أو استخدم Notion API عبر endpoint المستخدمين (`GET /v1/users`) وستجد `id` لكل مستخدم.
- المعرّف يكون بصيغة UUID مثل: `2b0d872b-594c-81a8-acc2-0002f0aa4abe`

### 2. معرّف المحادثة في تيليجرام (chat_id)

- اطلب من العضو أن يفتح محادثة مع البوت ويرسل له أي رسالة (مثلاً `/start`) — **هذه خطوة إلزامية**، لأن تيليجرام لا يسمح للبوت بمراسلة شخص لم يبدأ المحادثة معه.
- بعدها يرسل العضو رسالة إلى البوت `@userinfobot` وسيرد عليه برقم الـ chat_id الخاص به (رقم مثل `7469972624`).

### 3. تحديث سيكرت TEAM_MAP

1. افتح المستودع (repository) في GitHub.
2. اذهب إلى: **Settings ← Secrets and variables ← Actions**.
3. اضغط على سيكرت **TEAM_MAP** ثم **Update**.
4. أضف العضو الجديد إلى الـ JSON بنفس الصيغة:

```json
{
  "Mustafa":  {"notion_user_id": "...", "chat_id": 111111111},
  "العضو-الجديد": {"notion_user_id": "UUID-من-الخطوة-1", "chat_id": 222222222}
}
```

5. احفظ. التغيير يسري من الدورة القادمة مباشرة — لا حاجة لتعديل الكود.

## كيف يعمل الفحص كل دقيقة؟

جدولة GitHub Actions غير دقيقة (قد تتأخر ساعات)، لذلك نستخدم حيلة بسيطة: كل مهمة تبقى تعمل **حوالي 6 ساعات** (الحد الأقصى المسموح) وتفحص Notion **كل 60 ثانية**، والمهمة الجديدة تنتظر في الطابور وتبدأ فور انتهاء السابقة. النتيجة: فحص كل دقيقة تقريباً على مدار الساعة.

الإعدادات في ملف [`.github/workflows/notify.yml`](.github/workflows/notify.yml):

```yaml
schedule:
  - cron: "*/30 * * * *"   # طلب تشغيل مهمة جديدة كل 30 دقيقة (تنتظر في الطابور)
...
LOOP_MINUTES: "353"         # كل مهمة تفحص كل دقيقة لمدة ~6 ساعات
```

### إذا أردت تخفيف التكرار

- **فحص كل 5 دقائق:** غيّر `LOOP_MINUTES` إلى `"0"` و cron إلى `"*/5 * * * *"`
- **فحص كل 15 دقيقة:** غيّر `LOOP_MINUTES` إلى `"0"` و cron إلى `"*/15 * * * *"`

عدّل، اعمل commit، وسيعتمد GitHub الإعداد الجديد تلقائياً.

> **ملاحظات مهمة:**
> - هذا الأسلوب مجاني فقط لأن المستودع **عام (public)** — المستودعات الخاصة لها سقف دقائق شهري سينفد بسرعة.
> - جداول GitHub Actions تعمل بتوقيت UTC وقد تتأخر دقائق قليلة في أوقات الذروة.
> - يوجد workflow اسمه `Keepalive` يعمل شهرياً حتى لا يوقف GitHub الجدولة بعد 60 يوماً من عدم النشاط — لا تحذفه.

## التشغيل اليدوي (للاختبار)

من تبويب **Actions** في GitHub ← اختر **Notion → Telegram notifier** ← اضغط **Run workflow**. ستجد ملخص كل دورة في السجل بسطرين — سطر لكل وظيفة:

```
Summary: X tasks checked, Y notified, Z skipped
Portal: X Mayadeen approval tasks, Y created, Z updated, W archived, V failed
```

الوظيفتان مستقلتان: إذا فشلت وحدة (انقطاع Notion مثلاً)، الثانية تكمل شغلها بنفس الدورة.

## السيكرتات المطلوبة

| السيكرت | الوصف |
|---|---|
| `NOTION_TOKEN` | توكن تكامل Notion (Internal Integration) |
| `TELEGRAM_TOKEN` | توكن البوت من BotFather |
| `TEAM_MAP` | JSON يربط كل عضو بمعرّفه في Notion ورقمه في تيليجرام |
